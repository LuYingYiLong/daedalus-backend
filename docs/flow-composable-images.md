# Flow 可组合节点与批量图片工作流

Flow 的节点、图片处理和生成任务均由 Daedalus 执行。图片在节点间传递 Artifact 引用，运行记录不保存图片字节。本文对应 `flow-composable-1` 存储代际。

## 升级与数据范围

第一次启动新后端时，SQLite schema 27 会重建 Flow 专属表，并清理旧 Flow 产物和树顺序。Studio 旧代际的持久 outbox 不会重放。Chat 会话、Chat 附件、插件安装和供应商设置保持不变。清理标记持久保存，中途退出会在下次启动继续完成。

后端和 Studio 需要一起更新。测试使用临时用户目录；开发验证不会对正在使用的个人配置执行迁移。需要留存旧工作流时，应在启动新版之前使用旧版的「导出 Flow 数据」。本轮不提供旧数据导入兼容层。

## 节点与连接

| 分类 | 节点 |
| --- | --- |
| 参数 | 数字、布尔、颜色、尺寸 |
| 文本 | 文本替换、显式转文本；复用模板和合并 |
| 图片 | 读取工作区图片、缩放、裁剪、旋转／翻转、叠加、格式转换 |
| 列表 | 构建列表、取项、合并列表 |
| 批量 | 参数组、批量文生图、批量图生图 |
| 输出 | 媒体输出、保存图片 |

`src/protocol/flow-value-types.ts` 定义值校验和类型呈现元数据。`number` 必须有限，RGBA 分量为 0–1，尺寸为正整数。媒体引用必须属于当前 Flow，且 MIME、内容哈希与宿主记录一致。内置和插件执行器共用输入、输出验证器。

端口 `cardinality` 的 `one / many / one-or-many` 与 `multiple` 分开：前者描述单个值或列表，后者描述允许多条边。单值和列表不会隐式互换。通用输入使用蓝色、文本使用棕色，列表端口附加 `[]` 标识。需要转文本或从列表取单图时，使用对应节点。

普通图片生成节点固定输出「首张图片」和「全部图片」。图片处理节点可接单图或图片列表，输出始终是图片列表；多图叠加采用「底图列表 + 一张叠加图」。不会自动配对两组列表。

两条推荐流程：

1. 用户提示词 → 文生图的全部图片 → 缩放 → 裁剪／叠加 → 媒体输出；同时连接保存图片作为另一终点。
2. 参数组 → 批量文生图／图生图 → 缩放 → 叠加 → 媒体输出和保存图片。工作区图片读取节点可以给叠加图或图生图输入提供单图。

节点参数在连接后隐藏本地控件，断开后恢复原值。参数组支持增删、复制、粘贴多行提示词和稳定行 ID。新增节点定义通过注册表提供参数、端口、模型能力和执行器，通用 Picker 与参数组件无需逐个节点增加分支。

## 图片处理边界

- Sharp 0.35.4 在独立 Node 子进程运行，最多同时两个任务，每个任务 60 秒。
- 输入、叠加图和输出分别限制 64 MiB，每张图片最多 1600 万像素。
- 只接收静态 PNG、JPEG、WebP；拒绝 SVG、动画容器和损坏数据。
- 自动应用 EXIF 方向，转换为 sRGB，移除隐私元数据；原始文件不修改。
- 缩放 `contain` 为适应并补边，`cover` 为填充裁剪，`fill` 为拉伸。裁剪越界报错。
- 处理进程只接收二进制与严格操作参数，无任意路径、命令或网络接口。取消、超时和崩溃释放并发槽位。

缓存包含输入 Artifact 的内容哈希、完整配置和图片引擎指纹。被清理的产物不会命中可用缓存。工作区读取节点每次重新读取，避免文件变化后错误复用旧内容。

## 批量、恢复与保存

参数组最多 50 行，单行 1–4 张，计划总数最多 100 张。界面显示请求数和计划图片数。所有媒体调用共用全局 4、每供应商 2 的并发限制。

`flow_batch_items` 持久化每一行的实际参数、seed、请求与执行指纹、状态、任务 ID、结果、错误和尝试次数。成功图片按原始行序排列。部分失败仍允许成功项进入加工，Flow 显示 `partial_failure`；全部失败会跳过依赖后继。逐项事件携带 Flow、Run、Node、Item 标识，只更新相应运行订阅。

普通重试复用成功项，仅请求失败项；“重新生成全部”需要明确确认。随机 seed 在提交前持久化；记录 seed 不代表供应商支持 seed，也不保证模型输出可复现。当前 OpenAI 图片接口不承诺按 seed 复现。

明确的 429 最多再试两次，并读取 `Retry-After`。停止取消排队项并传播取消信号，已经完成的结果保留。具备 Provider Job ID 的任务恢复查询；请求发送后结果不明且没有查询 ID 时进入 `uncertain`，普通重试不会再次付费提交，需用户明确重新生成。模型不支持、未配置等提交前错误直接失败。

媒体输出提供虚拟化缩略图、单图预览、两图并排比较和参数元数据；批量节点显示逐项错误及重试入口。只挂载可见预览，延续画布 LOD、折叠、尺寸与端口几何机制。

保存图片通过已有工具审批、风险策略和审计。目标必须是 Flow 工作区内的相对目录；拒绝路径穿越和链接逃逸。文件名允许 `{runId}`、`{index}`、`{row}`、`{seed}`；默认不覆盖，重名追加序号。保存意图与哈希写入 `flow_image_saves`，按稳定图片标识处理重试，成功文件不重复写入。保存失败项保留独立错误。

## 供应商与插件

文生图复用现有媒体服务。图生图已补充 OpenAI 和百炼适配；不支持的供应商会明确报错，不会忽略输入图片。尺寸和单次张数仍受模型自身限制，超出支持范围会拒绝请求。

已通过本地 HTTP 合约测试验证 OpenAI JSON／multipart 请求和百炼多模态图片请求，包括输入图片、尺寸、seed／反向提示词传递和 429 信息保留。合约测试不调用真实付费 API，不能替代真实供应商测试。

可安装示例位于 `examples/flow-grayscale`。从 Studio 插件设置选择该目录安装、核对并信任后启用，即可在 Picker 中添加灰度节点。它声明 `flowNodes`、`flowTypedValues`、`flowMedia`，通过 `host.processImage` 调用宿主处理，仅使用授权 Artifact ID，不获得存储路径。示例附 manifest、执行器、类型和调试说明。

旧 Worker 不会被默默放宽：新增类型及媒体代理需显式能力协商，manifest 必须与实际注册一致。缺失、禁用、指纹不匹配或越权调用会明确失败。

## 发布与验证记录

Sharp 及其原生模块必须在目标平台安装和打包，不能复制 Windows 的 `node_modules` 到 Linux。SEA 发布包包含独立 `media/node(.exe)`、图片 Worker、Sharp 和匹配平台原生包。打包检查用发布目录中的 Node 和权限参数执行实际缩放任务。安装要求参见 [Sharp 官方说明](https://sharp.pixelplumbing.com/install/)。

本轮验证在 Windows 完成：后端类型与全量测试、Studio 类型／测试／生产构建、Flow Electron 功能回归、Windows SEA 和 npm dry-run。重点测试覆盖类型与媒体作用域、插件安装及能力拒绝、EXIF／像素／透明度、取消、批量部分失败与重试、已知任务 ID 恢复、未知提交保护、保存审批与幂等、Flow 数据重置范围。

真实 GPU 场景使用生产构建、1600×1000 窗口、DPR 1.25，硬件为 Ryzen 7 7435H 与 RTX 4060 Laptop GPU，Chromium GPU compositing 已启用：

| 场景 | 帧间隔 p95 | 帧间隔 p99 | 结论 |
| --- | --- | --- | --- |
| 200 节点／400 边，混合预览 | 13.9 ms | 20.8 ms | 达到本轮 25／50 ms 门槛 |
| 500 节点／1000 边压力场景 | 41.6 ms | 48.7 ms | 已记录压力数据，不作为本轮硬门槛 |

200 节点场景无长任务，各交互阶段分别达标；500 节点场景存在长任务和局部尖峰。缩放清晰度场景通过。该数据对应自动化测试的固定混合预览场景，不代表任意分辨率、媒体数量或硬件均能达到同样表现。
